# Security acceptance

- The frontend requires a fixed approved HTTPS origin, refuses redirects, and sends the Firebase bearer and App Check token in headers. Origin remains unset in the package. The candidate initializes a named modular Firebase app and obtains a new limited-use token for each operation. It rejects debug mode and fails closed when setup is unavailable.
- The Worker checks token signatures and claims and requires private authority and ingress bindings. The authority contract exposes `authorize({idToken,appToken,uid,authTime,appId})` and `owner({uid,authTime})` over a private binding. The reference verifies Firebase ID tokens with revocation checking and consumes App Check with `verifyToken(token,{consume:true})`. The current card owner's account and profile/NIJ binding are rechecked before lookup consumes a card.
- The Rules proposal permits an authenticated UID to get only its own allocation document with matching stored UID. The emulator exercises owner access, wrong UID, anonymous, list, client writes and unrelated records. The member REST call uses its Firebase bearer. The actual hosted authority identity and trust boundary require staging acceptance.
- SQLite exercises the D1 SQL for budgets, rotation, cooldown and conditional consumption. The card table holds an internal UID, digest, timestamps, authentication time and consumption state. Confirm that hosted telemetry excludes credentials and confirm approved retention and purge capacity. Per-UID budget is six per minute, global budget is 60 per minute, cooldown is 15 seconds and card lifetime is five minutes. Cleanup is bounded to 100 rows per table per invocation. Hosted ingress limits and quotas require platform verification.
- Concurrent SQL redemption allows one winner. Rotation during owner verification invalidates the old card. Firebase account verification and SQL consumption cross service boundaries. Review the acceptance implications of account state changing between those operations.
- The public SDK and emulator/mock results do not establish hosted App Check attestation or token consumption.

References: [Firebase web App Check](https://firebase.google.com/docs/app-check/web/custom-resource), [Firebase custom backend verification](https://firebase.google.com/docs/app-check/custom-resource-backend).
