## A. Hapus Data Jemaat

**Akar masalah terverifikasi di Firestore Emulator.** `database-jemaat.html` memanggil facade `sipapua-registration.js`, yang menyiapkan App Check lalu mendelegasikan ke `sipapua-spark-member.js`. `sipapua-member-session.js` juga memakai factory tersebut untuk operasi Spark. Ini jalur transaksi client Firestore, meski facade membungkusnya dengan nama operasi Callable. Batch menghentikan transaksi bila ada satu penolakan. Pada baseline, delete `users/{profileId}` dapat lolos untuk administrator aktif, tetapi create `registration_audit/profile-delete_{profileId}` terkena fallback deny. Akibatnya, SuperAdmin sintetis yang benar-benar login menerima `permission-denied` dan profil tidak berubah. Jalur Callable opsional di `functions/member-lifecycle.js` memiliki masalah terpisah: helper otorisasi generik saat itu memperlakukan Admin dan Viewer aktif sebagai manager delete.

**Kandidat selesai.** `member-delete.patch` memperbarui `firestore.rules`, `database-jemaat.html`, `sipapua-spark-member.js` dan `functions/member-lifecycle.js`. Untuk hapus profil pihak lain, Rules meminta dokumen `admin_users/{request.auth.uid}` berstatus `active` dengan role kanonis `master` atau `super_admin`. Kepemilikan diri tetap memakai UID yang dapat dicocokkan. Delete dan create audit harus terjadi dalam transaksi yang sama, dengan actor, target, path dan timestamp yang cocok. Audit tidak dapat diubah atau dibuat tanpa delete terkait. Validasi ID mencegah input path/duplikat. UI memakai role kanonis, menunggu hasil transaksi, dan mempertahankan hitungan kelompok terkonfirmasi. Kandidat Callable membatasi role kepengelolaan delete dengan daftar yang sama, tanpa mengubah role edit. Tidak ada migrasi Auth, penghapusan akun, atau penggunaan ulang NIJ.

**Bukti fungsional.** Firebase Auth dan Firestore Emulator memverifikasi bahwa SuperAdmin aktif menghapus satu profil, Master aktif menghapus empat sekaligus, dan masing-masing audit tersimpan. Admin biasa, SuperAdmin inaktif, delete tanpa audit, serta audit tanpa delete ditolak. Handler bulk diambil dari halaman dashboard yang dipatch dan dijalankan dengan DOM fixture serta transaksi emulator sungguhan. Dari enam profil sintetis, kelompok pertama terhapus dan kelompok kedua ditolak atomik. UI menyatakan **4 dari 6 terkonfirmasi**. Dialog sukses tidak muncul sebelum transaksi selesai. Browser dashboard penuh dan Callable hosted belum dijalankan.

**Gate deployment dan risiko.** Role/status akun SuperAdmin yang sedang dipakai di sistem aktif dan Rules yang terpasang **belum terverifikasi**. Tidak ada akses baca Firebase produksi yang tersedia dalam run ini. Ref lokal atau penolakan emulator tidak membuktikan path yang ditolak pada sistem aktif. Sebelum deployment, baca status akun dan revisi Rules dengan akses resmi, cocokkan role kanonis, rekonsiliasi aturan staging agar tidak mengganti perubahan lain, dan uji audit/rule candidate bersama UI serta rollback. Pengetatan delete langsung dapat memengaruhi caller legacy yang belum mengirim audit. Bukti patch hanya berlaku pada baseline yang diuji.

## B. Lacak Domba

**Akar masalah terverifikasi pada salinan halaman asli.** Kontrol awal sengaja disabled sampai Firebase Auth dan presence selesai. Inisialisasi lama memakai merge ke `presence/{uid}`. Dokumen lama yang memiliki key tambahan atau belum memiliki flag wajib gagal `validPresence()`. Browser dengan sesi Auth Emulator sungguhan mereproduksi pesan presence gagal dan tombol Pindai sekitar tetap disabled. Ini bukti penyebab lokal, bukan konfirmasi bahwa dokumen akun aktif memiliki bentuk legacy yang sama.

**Kandidat selesai.** `lacak-domba.patch` hanya mengubah `lacak-domba.html`. Transaction baca/ganti menulis proyeksi presence dengan key yang diizinkan, mempertahankan flag valid dan memberi default aman untuk flag yang hilang. Kontrol dibuka sesudah commit dan pemeriksaan sesi. Pergantian sesi mereset kontrol, heartbeat, dan hasil radar. Rules lokasi tidak berubah. `presence_locations/{uid}` tetap owner-only dan endpoint tetap membaca lokasi privat milik caller. Audit source Edge menunjukkan RPC `lacak_domba_scan_candidates` menerapkan sesi discoverable yang belum berakhir dan memakai akses service role. UI menerima nama dan jarak dalam rentang dari backend, bukan koordinat target.

**Bukti fungsional.** Chrome membuka baseline dan salinan dengan patch. Login dan pemulihan sesi setelah navigasi memakai Firebase Auth Emulator; normalisasi dan lokasi memakai Firestore Emulator. Sesudah patch, tombol aktif. Sebelum opt-in, lokasi belum tersimpan. Memilih Bisa Ditemukan meminta geolokasi sintetis, tersimpan secara privat, dan endpoint fixture memberikan hasil sesuai. Profil fixture yang tidak opt-in tidak muncul. Logout menonaktifkan kontrol dan membersihkan hasil. Rules Emulator menolak baca dan tulis koordinat oleh UID lain. HTTP fixture memvalidasi sesi lewat Auth Emulator dan membaca data Firestore sintetis. **Filter Edge/Supabase yang sebenarnya belum diuji lewat browser.**

**Gate deployment dan risiko.** PostgREST/PostgreSQL lokal serta konfigurasi layanan sintetis tidak tersedia pada run ini; Deno cached-only juga melaporkan dependency `@std/assert` tidak ada. Suite Edge/RPC sebenarnya **BLOCKED**, sedangkan browser dan Firebase Emulator **PASS**. Log aktif dan migrasi Supabase deployed belum diverifikasi. Masih perlu uji browser dengan Edge Function dan migrasi sungguhan pada lingkungan lokal/staging yang diizinkan, termasuk expiry consent, daftar blokir, radius, non-consenting, serta penolakan tanpa koordinat caller. Tidak ada perubahan schema atau policy Supabase. [Supabase Edge Functions](https://supabase.com/docs/guides/functions/quickstart)
